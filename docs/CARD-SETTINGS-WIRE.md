# Card settings wire v1

Only an active, authenticated Home Assistant admin using the integration's loaded entry may read or mutate configuration. The server checks `require_admin` and the current AuthManager principal and session before reading private settings, immediately before admitting persistence, and before returning private data. There are no card YAML settings, browser storage, or public source bindings. The public level projection adds `uninus_water_settings_entry`, an opaque ConfigEntry ID solely for scoping (not authorization); existing layout/display DTOs remain v1.

`uninus_water_control/config_get`: `{version:1, entry_id}`. Result:

```json
{"version":1,"entry_id":"<entry>","revision":"<hex>","source_snapshot":"<hex>","common":{"refill":null,"alarm":[0.3,10]},"zones":[{"id":"<zone>","name":"東區","tanks":[{"id":"<tank>","name":"東 1 桶","refill":{"use_common":false,"local":[0.4,1.5],"effective":[0.4,1.5]},"alarm":{"use_common":true,"local":null,"effective":[0.3,10]},"scale_max_m":2.5}]}]}
```

`uninus_water_control/config_save`: `{version:1, entry_id, if_revision, if_source_snapshot, changes}`. `changes` only permits `common` and `tanks`. `common` permits `refill` and `alarm` pairs or `null` (clear); `tanks` is a list of unique rows `{id, refill?, alarm?, scale_max_m?}`. Tank `refill`/`alarm` are objects with optional `use_common` (strict boolean) and `local` (pair or `null` to clear). A positive finite `scale_max_m` or `null` sets or clears the display maximum. Omission leaves a value untouched; individual local values survive opting in/out. Both numbers in each pair are required: refill `[lower_m,upper_m]` is ascending; alarm `[lower_m,delay_seconds]` has integral delay ≥1 (up to 2,147,483,647 seconds). All numbers must be finite, not booleans. Unknown keys/targets, duplicate tanks, invalid pairs, or opting into an unset common pair reject the entire request. A common pair can only be cleared if no tank still opts in after the transaction. Lengths: entry ID 26 uppercase HA ULID characters; zone/tank IDs 32 lowercase hex; tokens 64 lowercase hex. WebSocket envelope `id` and `type` are Core fields.

Save returns the same DTO as Get only after an atomic private Store write and independent physical readback. A Get after Save is safe; do not retry a Save automatically. `stale_revision` or `stale_source` means the submitted snapshot no longer applies; reopen/read current settings and review or cancel the draft. `readback_required` means no result can be confirmed by this connection (including an admitted write followed by source drift); a fresh Get is the recovery path. `settings_unavailable` means the private Store cannot be safely read; restore a valid backup rather than overwriting it. `entry_not_loaded`, `unauthorized` and `invalid_format` expose no private settings. Revision fingerprints include the selected entry, native data/options and durable generation; source tokens cover the selected entry's configured registry identities and their current eligibility, not the mutable name of a registered row or live sensor samples. A same-row rename is safe; removal/ID reuse does not authorize a replacement. Unregistered sensor names have no registry identity; normal live telemetry changes are not edits and cannot invalidate a draft. Native topology/safety writes cannot enter while the entry settings gate is held; no settings Save rewrites native ConfigEntry options or reloads the runtime.

New setting numbers use JSON binary64, with magnitude at most 9,007,199,254,740,991 (JavaScript's safe integer limit). Fractional values use normal binary64 decimal rounding; refill bounds must remain strictly ordered in that representation. The backend rejects out-of-range edits before persistence, including tokens Core has already decoded as rounded floats. Existing values from v0.2.0 may be read and carried forward unchanged at any finite representable binary64 magnitude; the legacy over-cap delay exception is for existing tank-local alarms only, not new delays or common alarms.

An open editor keeps its draft and both original CAS tokens in memory for the same authorized principal and entry across a connection interruption. It waits for any outstanding request to settle, then verifies the current entry and reads a fresh snapshot before allowing Apply. An advanced token requires discard and review; an interrupted, dispatched Save is unconfirmed even if the new snapshot matches the draft. Neither case is automatically rebased or resent. The editor discards the draft on close, denied authority, or loss or replacement of its entry scope.

An absent Store means untouched v0.2.0 per-tank thresholds and scales, no common defaults, and no implicit membership. A v0.2.0 downgrade ignores (and does not delete) the Store. Re-upgrade reads it without modifying the native options. A tank overlay anchored to changed native source bindings or legacy policy becomes dormant as a whole; it does not automatically transfer to the replacement source or overwrite newly edited v0.2.0 settings. Review the fallback values and explicitly save against a fresh read. Unknown Store versions are never overwritten. A later successful settings Save prunes orphaned or dormant tank rows. Low-level alarm/preview and gauge policy changes do not operate outputs or deliver notifications. A changed effective alarm pair resets only that tank's interval; unchanged intervals keep running. The separate write action is reserved to the HA native card editor (Dashboard edit → water card Edit → 套用整合設定); HA’s outer Save/Cancel is only Lovelace configuration. Native Options now points to that editor rather than offering a competing settings writer. Card-based topology edits, Recorder history and the final streamlined Options/SIM milestones are not part of this slice.
