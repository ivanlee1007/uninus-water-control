# 在 Home Assistant 加入補水總覽

「補水控制」卡片採用提案的繁體中文介面，讀取 UNiNUS Water Control 發布的水位、門檻預覽及輸出回報。新增卡片不會呼叫設備服務，也不會覆寫既有儀表板。

1. 在隔離 HA 測試機載入整合，到 **設定 → 裝置與服務 → UNiNUS Water Control** 新增整合，選第一桶的液位實體。區桶編輯須先完成整合的安全移轉；見[移轉與復原指引](TOPOLOGY-MIGRATION.md)。
2. 用管理員帳號開啟 **設定 → 儀表板 → 資源**（若未顯示資源管理，先在個人設定啟用進階模式）。新增 URL `/uninus_water_control/dashboard.js`，類型選 **JavaScript 模組**。該 URL 由有啟用 HTTP 的整合提供，只需登錄一次；YAML 管理資源的 HA 可依其原有方式加入同一個 URL，勿同時登錄兩次。
3. 在要使用的儀表板開啟原生編輯。新增卡片時可選「補水控制」，或在手動卡片貼上：

   ```yaml
   type: custom:uninus-water-dashboard
   ```

   如需完整可用寬度，可使用面板（Panel）檢視，只放這張卡。卡片依實際可用寬度調整區域與水桶欄數，不固定桶數。
4. 在「操作總覽」點水位數字可開啟 HA 原生 **更多資訊**；點各桶的狀態徽章可展開「詳細狀態」，也可開啟已設定的門檻預覽實體。水位量程需為各桶另行設定，未設定時不畫填水比例。
5. 管理員在日常卡片開啟該桶 **快捷參數**，調整補水上下限、低液位告警門檻與延遲及液位圖量程。可沿用共用設定或使用此桶個別值；只有明確按 **儲存此桶參數** 才保存並重新讀回。取消／Escape 不寫入。這是該桶的共用後端設定，會影響所有顯示此桶的卡片；目前門檻只影響唯讀預覽，不會自動補水或發送通知。
6. **編輯儀表板 → 卡片編輯器** 只調整此卡顯示範圍與詳細狀態等選項，使用 HA 外層儲存／取消，不修改共用參數、區桶或設備。隱藏一桶不是停用控制或關閉設備。
7. 到 **設定 → 裝置與服務 → UNiNUS Water Control → 設定** 管理區桶增減、正式名稱、來源及輸出綁定、安全啟用、最大運轉限制、共用及單桶參數。至少留一區，每區至少留一桶，可重名；移除需明確確認。Options 與快捷視窗共用同一後端設定和驗證，不各存一份。已啟用角色的修改須先停止並確認相關命令 settled；不以表單保存直接啟動設備。完整責任分層見 [C 方案](C-ARCHITECTURE.md)。

**控制邊界：** 只有日常卡片上已啟用的手動控制可經原生受控按鈕操作；編輯儀表板與編輯預覽不可操作設備。啟動須確認，未提供控制的按鈕維持停用。低液位與延遲告警為預覽，不代表輸出已開啟。卡片不提供自動補水、告警上限或直接繼電器控制。

**未確認套用：** 不要重送。用「重新讀取（捨棄草稿）」核對整合實際讀出的區桶與設定；若顯示移轉未完成或需要復原，依整合指引處理。缺少控制項不代表已實體關閉。介面契約見[區桶設定](CARD-TOPOLOGY-WIRE.md)。

**告警輸出紀錄：** 管理員可在日常卡片的「補水參數」選擇水桶，按「重新整理紀錄」。資料取自 HA Recorder，最多查詢最近 24 小時，僅顯示已核實的開／關變化（UTC），並標明實際涵蓋期間。未設定輸出、沒有可驗證的資料及涵蓋期間內沒有開關變化是不同狀態。紀錄不會回填至重新載入、重新綁定或記錄中斷之前，也不推斷觸發原因。詳見 [紀錄讀取介面](ALARM-HISTORY-WIRE.md)。

## 本機獨立驗證

在隔離的測試環境安裝 `requirements-test.txt` 和 `requirements-browser.txt`，用 `python -m playwright install chromium` 安裝 Chromium；已有受支援的本機 Chromium 可透過 `WATER_CHROMIUM_EXECUTABLE` 指定。執行 `python tools/verify_native_dashboard.py`；只驗證原生卡片編輯器可加 `--editor-only`，只驗證告警紀錄可加 `--history-only`。工具會啟動臨時、只綁定 `127.0.0.1` 的測試 HA，不需要任何正式站帳號或憑證。可加上 `--screenshots` 及輸出目錄另存檢查圖；再加上 `--reference` 與凍結的提案 HTML 路徑，比對同寬度的桌面、手機畫面與版面尺寸。

區桶專用驗證：執行 `python -m pytest -q tests/test_native_card_topology.py tests/test_native_lovelace_topology.py`。這些測試用合成實體與實際區桶移轉，驗證物理檔案讀回、原生服務權限與實際 Lovelace 編輯對話框。也可以用 `WATER_CHROMIUM_EXECUTABLE` 指定現有的 Chromium。
