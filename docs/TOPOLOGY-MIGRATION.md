# Topology handoff and recovery (release candidate)

[繁體中文使用與備份復原流程](TOPOLOGY-MIGRATION-ZH-HANT.md)

Do not use this candidate on live equipment. Completing the handoff does not verify the physical outputs, cutoffs, or off state. The configuration revision alone does not enroll an existing controller; ordinary never-enrolled controllers keep their previous behavior. A newly created controller also starts in this legacy-compatible mode, not as an enrolled writer.

## Planned maintenance window

1. Before installing the update, make and verify a native backup that includes all **Home Assistant settings**, including the integration, its settings and the entity registry. Download it and keep the previous compatible integration version with it. The first load after updating can migrate the entry to v2 even before enrollment. Reserve enough time for two full Core process restarts and recovery; do not begin if an interruption to control or monitoring is unacceptable.
2. Stop manual controls and wait for settled HA feedback without assuming that feedback proves physical OFF. Use and independently verify the device-side cutoff; keep it in effect through the window. Do not proceed if you cannot confirm the safe physical state and exclusive mapping independently.
3. In the integration’s native **Configure** flow, choose **Transfer topology to the integration store** and confirm the cutoff. A successful dialog requests enrollment; it is not a durability or readiness acknowledgment. The current owner cannot start a new run after the request, but it retains the same bound Stop path until it unloads. A reload does not advance the handoff.
4. Restart the whole Home Assistant Core process. It reads the saved request and legacy seed, then atomically writes and independently verifies the private image before handing the lifecycle witness to Core for persistence. During this step the entry reports that a fresh process is required. Allow normal Core persistence and use an orderly second restart; do not manually edit or force-flush Core’s storage.
5. Under **Configure → Topology transfer status**, wait for **Topology transfer complete** and verify that stable tank IDs, registered sources, thresholds and commissioned mappings match. If the status still asks for a restart or recovery, keep the cutoff in effect. Do not reset the integration or recreate old bindings. Make and download a new verified **Home Assistant settings** backup of the now-matching Core witness, integration settings and registry. Before the cutoff is released, confirm physical identity and safe operation through the site’s separate commissioning process.

## Missing, corrupt, or foreign image

A marked entry refuses setup if its owned image is missing, damaged, or does not match the entry and enrollment token. There is no manual-role or Start fallback to the retained Core migration seed, no guessed OFF, and no claim that equipment is off. Home Assistant monitoring/controls from this entry can be absent or unavailable. If loss is discovered after the entry has loaded, a new Start is denied; any still-proven Stop stays bound to its original registered output. Use the independent device cutoff and verify the actual state with the site’s approved procedure. An administrator must explicitly restore **Home Assistant settings** from the matching backup as a unit in **Settings → System → Backups**. Restore can replace unrelated settings as well. After restart, confirm identity and settings before allowing any control. Never mix components of different backup snapshots or delete, edit, or copy individual `.storage` files.

A rollback is a maintenance operation, not an automatic downgrade: keep the independent cutoff in effect; restore the complete verified **pre-install v1** backup and its compatible integration, not just older code or a Core config entry. An older integration refuses v2 even if no enrollment was requested. Review everything changed since the backup and confirm the physical configuration again before resuming. Neither restoring the file nor seeing HA feedback is proof of physical OFF. See the [official backup guide](https://www.home-assistant.io/common-tasks/general/backups/).
