# Topology WebSocket compatibility contract v1

Under the approved [C architecture](C-ARCHITECTURE.md), the shipped card no longer offers topology editing. Add/remove/rename/bind and safety commissioning belong to native integration Options. These authenticated v1 commands remain a backend compatibility/verification interface; they do not imply that a Lovelace editor should perform integration writes.

Additive commands on the existing authenticated HA connection: `uninus_water_control/topology_get` and `uninus_water_control/topology_save`. `config_get` and `config_save` v1 are unchanged. Every command uses exactly `type`, `version` (integer `1`), `entry_id` and the Core message `id`; Save also requires `if_revision`, `if_source_snapshot`, `zones`, `remove` and `changes`. The two tokens match the v1 settings tokens; same revision and one durable generation/CAS gate across settings, topology and protected Options.

Get/Save success shapes are identical: `{version, entry_id, revision, source_snapshot, zones, candidates}`. `zones` is an ordered array of `{id,name,tanks}`; `tanks` is an ordered array of `{id,name,level_sensor,refill_switch,alarm_switch,protected}`. A binding is `{entity_id,registry_id}` or `null` for unbound optional roles. Existing name-only bindings have a `null` registry ID and can only be carried forward unchanged. A missing registered binding is `{entity_id:null,registry_id:<stored row ID>}`: it can be carried forward unchanged and is shown as unavailable with no picker selection, never as a different row at the saved name. The operator must select the replacement explicitly, or explicitly clear an unprotected optional binding. `protected` is a server-owned boolean for the commissioned tank. `candidates` is an array of `{entity_id,registry_id}` with stable registered IDs, sorted by entity ID, not a promise that any particular role will accept the binding. All responses are admin-only; no control DTO or commissioning fields are writable.

Save takes complete ordered `zones` without `protected`; existing IDs must stay in their existing zone, new IDs are `null` and allocated by the server. Named arrays must retain one zone and one tank per zone. Existing untouched names carry forward exactly; new/edited names are trimmed nonblank strings of up to 128 Unicode code points with no C0/C1 controls. Names can repeat. For a changed binding both IDs must match the currently enabled non-integration registry record of the proper domain; existing unchanged fields can survive legacy or unavailable sources without inferring a replacement. Duplicate source picks and shared/same-device output conflicts reject changed mappings. The ordinary editor may rename protected labels but may not remove the protected tank or change its bindings. `remove` is exactly `{zones: [id, ...], tanks: [id, ...]}` using sorted IDs from the explicit operator confirmation; deleting a zone lists all persisted tanks it removes. `changes` follows `config_save` v1 and participates in the same write (only surviving existing IDs in numeric edits). At least one effective topology change is required on this route; settings-only saves continue to use `config_save`.

Revision/source conflicts are `stale_revision` and `stale_source`; malformed or unknown input is `invalid_format`; conflict with existing bindings is `binding_conflict`; missing/incorrect removal confirmation is `removal_confirmation_required`; protected differences are `protected_topology`. `topology_not_enrolled`, `topology_restart_required`, `topology_recovery_required`, `entry_not_loaded`, `unauthorized` and `readback_required` are distinct. Missing/uncertain acknowledgement never licenses a replay; verify through a fresh read. A success requires atomic private Store replacement, independent byte-source readback, and native projection reconciliation, without Core entry option edits or entry reload. Live manual Stop ownership is not replaced. No switch service is called by the editor.

For output conflicts, compare resolved registry rows, their current names and their physical device IDs. A known registered row's previous name does not reserve the name after a distinct row takes it. Unresolved outputs retain the conservative saved-name check, and resolvable name-only outputs also retain the same-device check.

After a conflict, **讀取目前設定（保留草稿）** compares freshly read settings without changing the original draft or CAS tokens. The current values are read-only; inconsistent settings/topology replies are not combined. **重新讀取（捨棄草稿）** discards the draft and opens a new baseline; changes, missing-source selection and Apply are explicit. Losing authority clears the draft and the current-values display.
