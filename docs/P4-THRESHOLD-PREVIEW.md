# P4｜補水與告警門檻預覽

先在隔離 HA 驗證設定、讀值與門檻判斷；這個增量不操作原始開關，也不改變 P3 的手動控制。Jingan 維持唯讀；現場門檻、單位、等值行為與綁定未確認前，不將測試值當作現場預設。

- 每桶可獨立設定補水下限與停止上限。以公尺設定，沿用現有液位實體對公分、毫米的換算。下限必須小於上限；這個預覽在液位等於下限時顯示「達補水門檻」，等於上限時顯示「達停止門檻」，中間顯示「門檻之間」，不推定水閥狀態。
- 低液位告警下限與延遲獨立於補水設定。液位在告警下限（含）以下連續達延遲才顯示告警；回升、來源無效、更換綁定或重載會清除計時，不追認舊區間。低液位告警是本次預覽規則，不代表已確認 Jingan 使用同一規則。
- 兩個功能預設未設定，且互不依賴；不因啟用手動補水或警報而自動啟用。依 [C 方案](C-ARCHITECTURE.md)，參數可在原生 Options 或日常卡片每桶快捷視窗管理，兩者共用唯一後端；Lovelace 編輯器僅改本卡顯示。狀態只透過原生唯讀實體發布，不宣稱通知已送出，也不解讀成任一實際輸出。
- 驗收：隔離 HA 原生儲存／重載、接近及等於門檻、連續告警／復歸、來源失效與同迴圈恢復、兩桶互不干擾、加刪改名及未設定相容。以試驗用服務記錄確認預覽不送開關命令。保留既有 P1–P3 測試。

正式自動致動、通知、完整操作／告警原因履歷與現場遷移另有驗收；有限告警輸出變化歷史已有獨立介面，不能取代完整履歷；不為此增量另開 PR。實體裝置的獨立關斷保護未驗證前，不啟用無人補水。

## 原生設定與實體

在 Home Assistant 的整合原生設定管理共用與單桶參數，或在日常卡片開啟該桶「快捷參數」。每項功能以完整數值對保存；可選此桶個別設定或沿用已有的共用值。清除個別設定與切換共用模式是不同操作。液位門檻用公尺、延遲用正整數秒，沒有現場預設值。保存使用同一個 Settings 交易及讀回，不靠卡片 YAML，也不為純參數變更重載控制器；有效告警規則改變才重設該桶連續計時，不改動無關桶。此操作不啟用或修改手動控制。

儀表板可從原生實體狀態讀取下列唯讀介面。兩種實體都提供 `attributes.uninus_water_thresholds`，形狀為 `{version: 1, zone_id, tank_id, kind}`，包含來源無效時的 `unavailable` 狀態；請用穩定的區域／水箱 ID 對應，不要猜測使用者可更改的實體 ID。

| `kind` | 原生領域 | 實體登錄唯一 ID | 狀態 |
| --- | --- | --- | --- |
| `refill_preview` | `sensor` | `<tank_id>_refill_preview` | `refill_threshold`、`between_thresholds`、`stop_threshold` 或 `unavailable` |
| `low_level_alarm` | `binary_sensor` | `<tank_id>_low_level_alarm` | `off`（尚未達延遲或已回升）、`on`（低水位連續達延遲）或 `unavailable` |

未設定的功能沒有實體；`unavailable` 不是 `off`。上述狀態不表示開關、閥門、送出通知或歷史告警的狀態。
