# 區域與水箱移轉、備份與復原

移轉只改變設定的儲存位置，不驗證實體輸出、不證明設備已關閉，也不會自動啟用設備。尚未申請移轉的控制器繼續使用原有設定；整合更新後，Home Assistant 仍可能在第一次載入時把整合項目升為 v2，**不會等到申請移轉才升版**。

## 更新之前：先保留可回復 v1 的備份

1. **在安裝或更新新版整合之前**，以管理員身分開啟 Home Assistant **設定 → 系統 → 備份**，建立一份包含完整 **Home Assistant 設定（Home Assistant settings）** 的手動備份。保留當時的相容舊版整合。只匯出卡片 YAML、歷史資料或單一設定檔不夠。
2. 等待備份成功，確認包含 Home Assistant 設定，下載到 HA 主機以外的安全位置；若有加密，另存金鑰／緊急工具包。標記為「更新前 v1」、記錄日期與整合版本。可行時，在不連接實體設備的隔離測試主機試還原，確認原本的區域、水箱與實體都存在。
3. 若已載入新版才備份，即使從未申請移轉，這份備份也可能已是 v2，不能當作舊版的降版備份。不要只換回舊版程式、刪除整合重建或手動修改儲存檔。沒有相符的更新前 v1 備份，就不能依此程序安全降版。

## 維護時段：申請、重啟、確認、另存 v2 備份

1. 預留兩次完整重啟及必要的復原時間。停止手動操作並等候回報穩定；用現場核准的方法操作並獨立確認**裝置側獨立關斷**與實際設備狀態。HA 的回報不能代替實體查驗；若不能確認安全，不要開始。
2. 在 **設定 → 裝置與服務 → UNiNUS Water Control → 設定**，選擇 **將區域與水箱移轉至整合儲存**，確認備份與裝置側關斷。送出只代表申請；**不是移轉成功**。同一個程序不會啟用新的控制歸屬；重新載入整合也不能取代完整重啟。
3. 完整重啟 Home Assistant Core。首次重啟會讀取先前保存的申請，寫入並核對整合設定，然後才更新由 HA 管理的移轉狀態。保持關斷；依畫面提示再正常完整重啟。若中斷但畫面仍指示完整重啟，保持關斷並依提示重啟、再查看狀態；若出現復原提示，依下節處理，不要重建輸出或清除移轉狀態。
4. 再開啟整合的 **設定 → 區域與水箱移轉狀態**。看到 **移轉完成** 才代表新設定已經核對且整合已載入。核對區域、水箱、註冊的感測器、門檻與安全啟用的對應。用 HA 備份另建並下載一份相符的 **Home Assistant 設定** 備份，標記為「移轉完成 v2」，勿覆蓋更新前備份；日後設定變更後重新備份。依現場程序再確認實體輸出身分及安全運作，才考慮解除裝置側關斷。

## 看到「需要復原」或整合未能載入

1. 先使用裝置側獨立關斷、確認實際設備狀態。冷啟動無法證明哪個輸出屬於整合時，整合不會猜測性地發送「停止／關閉」或「啟動／開啟」指令，也不會回退到留存的舊控制設定。HA 上控制消失或顯示無法使用，**不代表設備已關閉**。已載入後才失去設定時，原本仍可證明歸屬的停止路徑與冷啟動情形不同；任何 HA 狀態都不能代替裝置側關斷。
2. 請管理員在 **設定 → 系統 → 備份** 選取或上傳同一時間點、已知可用的「移轉完成 v2」備份，選擇並明確確認還原 **Home Assistant 設定**。需要金鑰時用該份備份對應的金鑰。此操作會覆蓋其他整合、儀表板、自動化等設定；先檢查影響並安排停機，還原完成後讓 HA 完整重啟。並非由本整合寫入或還原 HA 的原始檔案。
3. HA 的整合項目、整合私有設定與實體登錄必須來自**同一份備份**。即使兩份備份屬於同一次移轉，也不要把某份備份的 HA 項目與另一天的整合設定拼在一起。不要編輯、刪除或個別複製 `.storage`。重啟後重新確認 **移轉完成**、區域與水箱、門檻及實體對應；在現場確認安全之前，保持裝置側關斷。
4. 若管理員決定降版，使用**更新前**驗證過的完整 v1 Home Assistant 設定備份及同一份備份對應的相容舊版整合，並遵守相同的維護與實體查驗步驟。這會失去備份之後的設定變更；整合**不會自動降版**。若沒有相符備份，保持關斷並聯絡管理員，不要嘗試重新配對以解除防護。

備份建立、下載、金鑰與還原畫面請見 [Home Assistant 官方備份說明](https://www.home-assistant.io/common-tasks/general/backups/)。資料庫歷史、外部資料及附加元件的備份另依現場政策選擇；不能取代完整的 Home Assistant 設定。
