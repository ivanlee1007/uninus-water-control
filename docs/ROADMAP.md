# UNiNUS Water Control｜目前範圍與後續驗收

## 現行產品契約：C 方案

以 [C-ARCHITECTURE.md](C-ARCHITECTURE.md) 為本輪現行契約。P1–P4 是分段開發紀錄，不因名稱或階段完成而宣稱完整補水產品已驗收。舊階段要求的「卡片完全唯讀／全部使用 Tile」及後來的「卡片編輯器寫入共享設定」，都由核准的 C 方案取代。

- 區域從一區起、每區從一桶起，數量不固定；區名和桶名可編輯、可重複，stable ID 不依名稱或順序。
- 每桶指定一個 HA sensor 液位來源；補水與告警可分別綁定可留空的 switch。離線／遺失來源必須誠實呈現，不因同名實體出現而默默換綁。
- 卡片依實際容器寬度自適應，不以固定兩區或八桶作限制。保留液位圖與狀態摘要，More info、原生設定及實體選擇沿用 HA。
- 原生 Options 負責區桶清單、綁定、安全啟用、最大運轉限制、共用預設及原生參數表單。日常卡片提供管理員單桶快捷參數；兩者使用同一份後端設定、CAS／來源驗證及讀回，不各存一份。
- Lovelace 編輯器只選本卡顯示範圍與外觀；外層儲存／取消不改整合參數。快捷視窗取消不寫入，明確儲存才影響所有顯示該桶的卡片。

## 已交付能力的驗收邊界

### 清單與唯讀監看

原生 Config／Options 建立、增減、改名與修改來源；每桶提供原生液位實體。需驗證來源更換、無資料、同名、Registry 更名／同名接手、最小區桶數、保存後重開及重新載入。資料／設定錯誤不得臆測為正常。

### 自適應卡片與快捷參數

支援多區多桶、門檻預覽、量程、受保護手動控制、有限告警輸出歷史。需驗證 1/2/3/4+ 欄、窄容器、長名、不可用、單位更改、正常 telemetry 不打斷焦點、權限變更後隱藏頁清理。快捷保存須經真實後端與新讀回；卡片顯示設定不得呼叫私有設定寫入或設備服務。

### 單桶手動控制

目前只允許一桶啟用受保護手動補水／告警，兩種角色各自選配。後端掌管開始、停止、故障、輸出 Registry 身分與最大運轉上限；卡片只呼叫整合提供的 button 實體，不直接操作原始 switch。

需區分送出、設備回報與物理出水。停止未知不顯示已停；測試 setup 失敗後重試、遲到命令、卡住的 OFF、權限、來源失效、卸載及 HA STOP。軟體等待期限與重試不等於硬體安全截止。

### 門檻與歷史

補水上下限與獨立低液位延遲目前是唯讀預覽，修改不會自動補水、開告警輸出或發通知。歷史是有連續性證據的告警輸出開／關變化，不是完整操作原因／操作者稽核。見 [預覽語義](P4-THRESHOLD-PREVIEW.md)及[歷史介面](ALARM-HISTORY-WIRE.md)。

## 仍未完成的完整產品範圍（保留，不因本輪修復刪除）

1. **正式自動補水**：自動狀態機、啟停等值規則、故障恢復、重啟／來源遺失政策，以及與手動控制的仲裁。
2. **正式告警通知**：選定通知管道、觸發／恢復與重複抑制；不把 binary_sensor 預覽當成通知已送達。
3. **多桶控制政策**：是否共用管線／泵浦、並行限制、排隊與輸出歸屬；目前不能從多桶清單推論支援多桶致動。
4. **完整操作與告警履歷**：操作者、命令／結果、故障及恢復原因；與目前 Recorder 輸出變化分開。
5. **原站與實機驗收**：確認現場來源、單位、門檻等值、裝置層 timeout、獨立關斷與實際出水／停止，不複製疑似跨區錯綁。新舊控制器不得同時控制相同輸出。
6. **發布／部署**：軟體 PR、Hosted CI、版本 Release、HA 安裝與現場切換分別驗收。Jingan 本輪不寫入、不部署、不致動；HACS 公開發布及現場變更需另行授權。

## 測試基線

本輪沿用 HA Core `2025.12.0` 與其對應 frontend，並非宣稱最新版或所有 HA 版本皆相容。原生 Core／瀏覽器合成設備測試與物理驗收分開；測試數量、綠燈或表單勾選不能取代獨立硬體保護證據。
