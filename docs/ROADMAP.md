# UNiNUS Water Control｜開發順序與驗收

## 產品需求（不因分段交付而縮減）

- 區域從一區起、每區從一桶起，增減不限固定東西區或八桶；區名和桶名可編輯，名稱不當主鍵。
- 每桶一個由使用者指定且可更換的 HA `sensor` 液位來源，補水與告警各有獨立、可留空的 `switch` 綁定；未綁定只影響相應功能。
- Dashboard 根據各區與卡片實際可用寬度自動換列；不將固定兩區／兩欄的示範規格當限制。沿用核准的離線 Demo v4 操作原則，外觀服從 HA 原生元件。
- 原生優先：新增與設定使用 HA Config Flow / Options Flow、原生 Entity／Text／Select／確認表單；例行操作優先用原生 Tile、Button、Number、Switch、History 與 More info。設定綁定不在 Lovelace 卡片編輯器。自訂範圍只限原生無法完成的行為，不另造整套元件庫。

## P1｜原生設定 → 原生液位實體（本次第一個增量）

在隔離 HA 新增整合，建立第一區與第一桶；在整合選項中增減、改名、修改每桶實體選擇。設定讀回、重載與狀態追蹤後，每桶有可放在原生 Tile 上的唯讀液位實體。儲存、刪除配置、重載都不觸發任何繼電器。此階段不執行任何補水或告警控制，不自動寫入 Lovelace，也不提供切換生產設備的按鈕。

預定驗收：原生 HA Core Config/Options flow 實際送出 → Core 持久化設定 → HA 感測實體更新，並核對來源更換、無資料、同名與最小區／桶數。瀏覽器實點與真正設備驗收各自獨立，不用測試 Core 的模擬狀態冒稱已做實機。首個測試基線固定 HA Core `2025.12.0`，並非宣稱最新版或目前已支援所有版本。

## P2｜可跟隨清單的自適應原生總覽

- 以 HA 原生區段／Tile／Heading 呈現多區與各桶即時狀態；讀值、告警關係和實際輸出回報分開。原生配置採標準 dashboard schema。
- 驗證原生 Sections 能否同時滿足任意增減、區內按實際可用寬度重排、原生編輯與不覆寫使用者 Dashboard。若原生不足，再用最薄 view strategy 產生原生卡片；若僅區內 adaptive geometry 不足，隔離為薄布局層，仍由 HA 渲染卡片、按鈕、歷史及設定。不能拿可響應的固定兩欄當作驗收。
- 驗收增減桶後重排、長名、不可用、1/2/3/4+ 欄與不滿一列、窄寬容器不裁切；同欄寬比較原生實際瀏覽器畫面。

## P3｜隔離環境的單桶手動補水與告警

- UI 用原生可授權控制實體，絕不以卡片直接切未受保護的原始輸出。後端區分送出、設備回報、物理出水證據；停止回報未知不顯示已停。驗證手動停機優先、延遲／遺失／重複回報、來源失效、HA 重啟、操作權限與最大運轉時限。
- 補水和告警各自選配；配置參照不等於有權致動。跨區感測器與共享輸出先以現場與來源設定驗證，不能假定是八個完全獨立的實體。沒有裝置層 timeout 和保護的證據，不啟用無人運轉。

## P4｜完整流程、原站遷移與發布

補水門檻、獨立告警門檻與延遲、相關通知與操作／告警歷史；驗證原站實際門檻等值和依來源觸發行為後，明確批准新舊差異，不複製疑似跨區錯綁。保留舊控制器作回退，但不得與新控制器同時控制相同輸出。Jingan 本輪維持唯讀；相容性、實機切換、HACS 公開發布需另行驗收／授權，GitHub 私有開發儲存庫不是 Release。
